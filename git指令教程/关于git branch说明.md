\# branches（分支）通俗理解

仓库就像一份文档，\*\*分支 = 这份文档的独立副本，互相隔离\*\*，你可以在不同副本上改东西，最后再合并。

`main` 就是你现在正在用的\*\*主分支（主干）\*\*，相当于稳定原版，一般用来放可以正常跑、最终上线的代码。



\## 举个贴合你 MATLAB 项目的例子

\- `main`：放能正常运行、最终版本的脚本，不乱在这里直接改实验代码

\- 新建分支 `dev`：专门用来调试、改算法、加新功能，在这里随便改、改错、删代码，\*\*不会弄坏 main\*\*

\- 新建分支 `test\_fft`：专门测试某一段fft代码，测试完没问题再合并回 dev，最后合进 main



\## 核心几条命令（你现在这个仓库直接能用）

```bash

\# 查看所有本地分支，带\*的是你当前在的分支

git branch



\# 创建一个叫 dev 的新分支（只创建，不切换过去）

git branch dev



\# 创建并且立刻切到 dev 分支（最常用）

git switch -c dev



\# 切回主分支 main

git switch main



\# 把 dev 分支的改动合并到 main（先切到main再执行）

git merge dev



\# 删除本地分支（合并完、没用了再删）

git branch -d dev

```



\## 远程分支（github网页上看到的 branches）

你本地的分支，push 之后才会同步到 github 网页的 Branches 页面：

```bash

\# 把本地dev推到github远程，远程也会出现dev分支

git push -u origin dev

```

> `-u origin dev`：绑定本地dev和远程origin/dev，之后直接 git push 就行



\## 什么时候适合用分支？

✅ 写新功能、尝试新算法

✅ 做对比实验（比如两套参数、两种方案）

✅ 多人协作，A改A的模块，B改B的模块

✅ 怕改错把主代码搞崩，先在分支里面折腾



\## 简单工作流（单人写代码推荐，很适合你的matlab项目）

1\. 在 `main` 保持一份稳定代码

2\. 新建 `dev` 分支，日常写代码、调试都在 dev

3\. dev 测试跑通、没问题了 → 切回 main，`merge dev` 合并

4\. 合并完，main 永远是可用版本



\## 容易混淆的点

\- 分支不是复制一份全部文件存两份！git 底层是记录改动快照，很省空间

\- 切换分支的时候，本地文件夹里的文件会\*\*自动变成这个分支对应的版本\*\*，切换前记得 commit 保存改动，不然会丢

\- 冲突：同一个文件\*\*同一行\*\*，两个分支改的不一样，merge 的时候就会出现冲突，需要手动选择保留哪一份



\## 和你刚才的ssh关联

ssh 只是【传输通道】，负责把分支代码上传下载；分支是【版本隔离机制】，两件独立的东西。
